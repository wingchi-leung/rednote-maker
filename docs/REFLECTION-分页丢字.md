# 反思报告：预览/导出时部分文字「直接没了」

## 问题现象

文字转图片时，某些段落没有出现在下一页，也没有出现在当前页——在界面上看起来就是「这一大段文字不在下一页，直接没了」。

## 根因分析

1. **卡片是固定高度 + overflow:hidden**  
   预览区域和导出用的卡片都是固定尺寸（如 450×600 预览、900×1200 导出）。内容区使用了 `overflow: hidden`，超出部分会被裁掉，不会换到下一页。

2. **分页只按「字数」估算，没有按「渲染高度」**  
   分页逻辑用 `maxCharsPerPage = 1000` 等字符数上限来切页。但同样 1000 字：
   - 纯段落、长句、少换行 → 行数少，可能勉强能放下；
   - 列表多、标题多、短句多、换行多 → 行数多，实际渲染高度远超一屏，底部会被裁掉。

3. **等效「字数」估得过少**  
   原先 `estimateBlockChars` 对标题、列表、空行等的等效字数偏小，一页里塞进的「块」过多，渲染后容易溢出，溢出部分就被裁掉，看起来像「丢了」。

4. **大块切分时单块仍可能过大**  
   `splitOversizedBlock` 里用 `maxCharsPerPage - 50` 作为 chunk 大小，单页仍可能接近 1000 字，在列表/标题多的场景下依然容易超高一页。

所以：**不是分页算法「漏算」了某段文字，而是把本应一页显示的内容估少了，导致一页里实际渲染高度超过卡片，多出来的部分被 overflow 裁掉，看起来像「没了」。**

## 修复措施

1. **降低单页字数上限**  
   将 `EXPORT_CONFIG.maxCharsPerPage` 从 1000 调整为 650，从源头上减少单页内容量，降低溢出概率。

2. **按「等效高度」加重块权重**  
   在 `estimateBlockChars` 中：
   - 标题、列表、空行、代码块等占垂直空间多的块，等效字数上调（如标题 +28/级、列表 +18、空行 22、代码 ×1.8）；
   - 段落按行数加权重：多出的换行每行约 +24 等效字，使「多行段落」更早触发换页。

3. **大块切分更保守**  
   - 单块切分时使用 `maxCharsPerPage * 0.85` 作为 chunk 上限，避免单页顶满上限；
   - 判断「剩余是否整块压在一页」时用 `remaining.length <= chunkSize`，避免最后一截仍接近整页导致溢出。

4. **统一使用配置常量**  
   所有调用 `calculatePages` 的地方改为传入 `EXPORT_CONFIG.maxCharsPerPage`，避免多处写死 1000，以后改配置即可全局生效。

## 为何容易反复出现

- **字数与高度不是线性关系**：字体、行高、主题、列表/标题样式都会改变「每字占用的垂直空间」，单靠字数上限容易在部分场景下偏乐观。
- **没有按真实渲染高度反馈**：分页是纯逻辑计算，没有用实际 DOM 高度或 canvas 测量来校验「这一页是否真的没溢出」，所以一旦估算偏激进就会在特定内容下复现。
- **默认值偏大**：1000 字/页在「理想排版」下可行，但在列表、标题多的笔记里经常超高一页，需要更保守的默认值。

## 后续建议

1. **单页上限可配置**：若用户反馈「页数太多」，可在设置里提供「每页字数」或「紧凑/标准/宽松」分页档位，对应不同 `maxCharsPerPage`。
2. **可选：按主题/字号微调**：若后续支持多字号、多行高，可将 `maxCharsPerPage` 或等效权重与主题/字号绑定（例如字号大时略减单页字数）。
3. **长期可考虑「测量分页」**：在无头环境或隐藏 iframe 中渲染一页、测量高度，超则把最后一块移到下一页并重测，可从根本上避免溢出，但实现和性能成本较高，可作为后续优化。
